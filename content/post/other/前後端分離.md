說明前後端分離的基本概念、優點，以及導入時需要承擔的成本。
<!--more-->

## 前言

前後端分離是將瀏覽器端應用與後端 API 分成可獨立開發、測試及部署的元件。兩者通常透過 HTTP API 溝通。

## 優點

1. 獨立部署：例如 Angular 前端與 Spring Boot API 可以分別發布，修改靜態頁面時不必重新部署後端。
2. 職責清楚：前端專注互動與呈現，後端專注商業邏輯、資料與權限。
3. 技術選擇彈性：靜態資源可由 CDN 或 Web Server 提供，API 則可依負載獨立擴展。
4. 測試與協作更容易：前後端可依 API 契約平行開發，並分別執行自動化測試。

## 需要付出的成本

1. 必須管理 CORS、驗證、API 版本與錯誤格式。
2. 前後端需要共同維護 API 契約，避免介面變更造成相容性問題。
3. 部署元件與監控範圍增加，初期架構及維運成本也會提高。

因此是否採用前後端分離，應依團隊規模、產品生命週期與部署需求決定，而不是單純以效能作為判斷依據。
