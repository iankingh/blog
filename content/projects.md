## 個人技術網站：把學習變成可以分享的作品

這個網站用來保存全端開發、AI 規劃與工具使用的學習紀錄，也讓第一次認識我的人有地方閱讀實作與思考。RPG 冒險面板將文章當作探索紀錄，把持續寫作呈現為累積經驗的旅程。

![個人網站首頁：全端工程師與 AI 規劃師介紹、GitHub 入口與 RPG 營地插畫](/images/site-home.png "本機新版首頁，2026-10-05")

### 設計目標與取捨

- **閱讀與展示都有入口。** 首頁先介紹我，再呈現最新學習紀錄；讀者可以閱讀筆記，或從右上角的 GitHub 圖示了解更多。
- **用風格表達持續學習。** 保留像素營地、角色與技能圖鑑，導覽同時使用「作品」「筆記」等直覺名稱。
- **維護成本保持簡單。** 內容存為 Markdown，網站由 Hugo 產生靜態頁面，不需要常駐後端服務或資料庫。

### 版面與資料如何組織

文章放在技術筆記區，以分類、標籤與歸檔提供不同閱讀入口。每篇文章可提供摘要、更新時間與精選排序，內容與畫面分開維護。

技能定義集中在資料檔，首頁、關於頁與技能圖鑑共用。每篇相關公開筆記累積 1 EXP，每 10 EXP 升 1 級；**Lv. 表示筆記累積進度**，讓學習紀錄有趣且定義清楚。作品案例獨立於筆記區，不計入筆記數或 EXP。

### 全文搜尋與互動

Hugo 在建置時產生只包含公開技術文章的 JSON 索引。讀者開啟搜尋時才載入，後續在同一頁使用快取；標題、標籤與正文都能比對，結果保留精簡摘要。

載入失敗時可以重試，沒有結果時提供提示。搜尋使用原生 dialog，支援 `/` 開啟與 Escape 關閉；手機導覽、深淺色切換及程式碼複製由原生 JavaScript 處理。

### 自動部署與工程品質

推送至主分支後，GitHub Actions 使用固定的 Hugo Extended 版本建置。建置階段檢查產出的頁面，再由獨立發布階段更新 GitHub Pages，讓產物通過檢查後才上線。

文章中的 HTML 與 JavaScript 範例以程式碼呈現。共用頁首套用 CSP，搜尋結果使用純文字建立，避免把文章內容當作互動程式執行。版面提供手機排版、目錄、可捲動的程式碼與表格、跳至主要內容及鍵盤焦點提示。

### 基礎主題與本站修改

網站以 [Hugo NexT](https://github.com/hugo-next/hugo-theme-next) 為基礎，保留其主題與既有內容配置。本站的 RPG 版面、技能資料、作品頁、精選筆記、搜尋互動與部署檢查由專案中的版面覆寫及靜態資源維護。

這是一份本站實作的整理；上游主題、外部工具及文章參考來源都保留各自的來源說明。

### 目前限制與下一步

- 靜態網站沒有帳號或編輯後台；內容更新需要修改 Markdown 並重新建置。
- 搜尋索引適合目前的文章規模；文章量持續成長時，需要再量測索引大小與搜尋速度。
- 技術筆記依各篇標示的環境驗證，較早文章仍需逐步更新。
- 目前以學習筆記與 GitHub 為主要入口，其他專案案例會在整理完成後補上。
